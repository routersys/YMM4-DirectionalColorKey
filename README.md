# 方向色分離キー for YMM4

[![License](https://img.shields.io/badge/license-LGPL-blue.svg)](#)
[![.NET](https://img.shields.io/badge/.NET-10.0-purple.svg)](#)
[![Release](https://img.shields.io/github/v/release/routersys/YMM4-DirectionalColorKey.svg)](https://github.com/routersys/YMM4-DirectionalColorKey/releases)

---

YukkuriMovieMaker4（YMM4）上で動作する、背景色から各画素の色への変位の方向をOklab色空間で調べ、前景のアルファと色を推定して背景を透過する映像エフェクトプラグインです。
背景だけを写した参照画像と学習済みモデルを使わず、入力された映像と、前に処理したフレームで求めた結果だけを使います。
背景色を指定するだけでキーイングできます。
「前景色」は「スケール決定」が前景色指定のときだけ、「不透明基準値」は不透明基準のときだけ、設定欄に表示されます。
前景層数、不透明基準値、ノイズ閾値、色シグマ、エッジ柔らかさ、スピル除去、スピル許容の7項目はアニメーションに対応しています。

## 概要

本プラグインはYMM4の映像エフェクトとして動作し、エフェクトの種類一覧では「方向色分離キー」として表示されます。カテゴリは合成です。

指定した背景色と各画素の色をOklab色空間へ変換し、画素の色から背景色を引いた差を求めます。この差を変位と呼びます。近くにあって色も近い画素どうしで変位の方向を平滑化したあと、方向の似た画素を「前景層数」で決めた数のまとまりに分けます。このまとまりが前景層です。各前景層は代表の方向を1つ持ち、この方向を前景層の方向と呼びます。前景層ごとに、変位が前景層の方向へどれだけ伸びれば不透明とみなすかを表す長さを決めます。この長さをスケールと呼びます。

また、画素ごとに前景の色を推定します。前景の色は、背景色が混ざる前の前景そのものの色です。パラメータの「前景色」とは別です。推定は、前景の色が確かな画素から始め、その色を周りの画素へ伝えて行います。ここまでの処理をまとめて解析と呼びます。

解析の結果から、各画素のアルファを求めます。変位の長さが「ノイズ閾値」の半分に満たない画素と、素材でアルファが0の画素は、透明にします。ほかの画素のうち、前景の色を推定できた画素では、画素の色が背景色とその前景の色を結ぶ線分の近くにあれば、アルファを前景の色から求めます。線分から離れた画素と、前景の色を推定できなかった画素では、変位がどの前景層の方向とも90度以上の角をなすなら、透明にします。そうでなければ、前景層の方向とスケールから求めた値と、画素に残る背景色の色みから求めた値のうち、大きいほうをアルファにします。そのうえで、背景の色かぶりを取り除いた前景を出力します。

画素ごとの解析はComputeWeaveの計算シェーダーがDirect3D 12で実行し、前景層の方向とスケールはCPUで求めます。各画素のアルファと出力の色は、Direct2Dのピクセルシェーダーが計算します。YMM4のDirect3D 11側とComputeWeaveのDirect3D 12側は、共有テクスチャと共有フェンスで接続します。この接続で、素材を解析へ渡し、推定した前景の色をDirect2Dへ渡します。そのため、画素をCPUへ読み戻しません。素材が前回の解析から変わったかどうかは、変わった画素の数を表す整数1つをGPUからCPUへ読み戻して判定します。素材の範囲と画素と、「背景色」「前景色」「スケール決定」「前景層数」「ノイズ閾値」「色シグマ」「不透明基準値」が変わらないフレームでは、前回の解析の結果をそのまま使います。解析するフレームでは、前景層の方向を求めるための集計値も読み戻します。「スケール決定」が不透明基準なら、スケールを求めるための集計値も読み戻します。接続を使えないときの受け渡しは、「制限事項」に書いています。

このエフェクトはAviUtl向けのEXO出力には対応していません。

## インストール方法

1. [Releases](https://github.com/routersys/YMM4-DirectionalColorKey/releases/latest)ページから最新のプラグインファイル（`.ymme`）をダウンロードしてください。
2. YMM4が起動していないことを確認し、ダウンロードしたファイルを実行してインストールします。
3. YMM4を起動し、タイムライン上のアイテムに映像エフェクトを追加します。
4. 映像エフェクトの種類として「方向色分離キー」を選択してください。

## 主な機能

### 1. 背景色からの変位と方向

変位と方向は、Oklab色空間で求めます。Oklab色空間は、色の差が見た目の差に近くなるように作られた色空間です。Oklabでは、色を明るさのLと、色みのaとbの3つの値で表します。Lは黒で0、白で1です。「ノイズ閾値」「色シグマ」「スピル許容」とスケールは、Oklabでの長さです。たとえば0.02は、黒から白までの長さの50分の1です。

背景色と画素の色は、sRGBから線形RGBを経てOklabへ変換します。線形RGBは、sRGBの値を光の強さに比例する値へ直したものです。半透明の画素は、不透明にしたときの色へ戻してから変換します。各画素の方向は、変位を長さ1にした向きです。アルファが0の画素と、変位の長さが「ノイズ閾値」に満たない画素は、方向を持ちません。方向を持たない画素は、前景層とスケールの計算に使いません。

「ノイズ閾値」は、方向を持つ画素の変位の長さの下限です。前景の色の推定には使いません。出力では、変位の長さが「ノイズ閾値」の半分に満たない画素を、ほかの条件によらず透明にします。変位の長さが「ノイズ閾値」に満たなくても、その半分以上ある画素は、「前景の色とアルファ」に書いた方法でアルファを求めます。「ノイズ閾値」を上げると背景のむらを前景と取り違えにくくなり、下げると背景に近い淡い前景を残しやすくなります。

### 2. 方向場の平滑化

全画素の方向の集まりを、方向場と呼びます。方向場は、色の近い画素どうしで方向を平均して平滑化します。各画素では、その画素を中心とする9×9画素の範囲にある方向のうち、中心の画素の方向とのなす角が90度未満のものを選びます。選んだ方向に重みを付けて平均し、長さ1に戻します。重みは、中心の画素からの距離が短いほど、中心の画素と色が近いほど、方向が揃っているほど大きくなります。この処理を5回繰り返します。平滑化した方向は、前景層への分割と、「スケール決定」を不透明基準にしたときに画素を前景層へ割り当てることにだけ使います。平滑化するのは方向だけで、変位そのものは変えません。

「色シグマ」は、色がどれだけ離れると重みが小さくなるかを決める幅です。上げると色の離れた画素どうしでも方向が混ざり、下げると色の境目で方向が混ざりにくくなります。「色シグマ」は、前景層の方向とスケールを通してだけ出力に効きます。前景の色からアルファを求める画素には効きません。

素材の画素の一部だけが前回の解析から変わったときは、変わった画素の周りだけ平滑化をやり直します。変わった画素が全体の25%を超えたときは、平滑化を全体でやり直します。素材の画素数か、「背景色」「ノイズ閾値」「色シグマ」のどれかが変わったときも同じです。

### 3. 前景層への分割

方向場は、k平均法で前景層に分けます。各画素を、その画素の方向に最も近い方向を持つ前景層へ割り当てます。次に、前景層ごとに割り当てた画素の方向の平均を求め、前景層の方向をその向きにします。この2つの処理を最大12回繰り返します。どの前景層にも画素が割り当てられ、どの前景層の方向もほとんど動かなくなったときは、12回に達する前でも止めます。

「前景層数」は、方向場を分ける前景層の数です。1から4までの整数に丸めて使います。画素が1つも割り当てられなかった前景層は、方向を背景色から白へ向かう方向にして残します。前景層は出力を分けるものではありません。アルファを求めるのに使う方向とスケールを決めるための、画素のまとまりです。

最初の解析のときと、「前景層数」が変わったときは、背景色から白へ向かう方向を1つ目の前景層の方向にします。背景色が白のときは、Lが増える向きをこの方向として使います。2つ目以降の前景層の方向は、この方向をaとbの平面で回して作ります。回しても方向のLの成分は変わりません。回す角度は、2つ目が180度を前景層の数で割った角度で、3つ目はその2倍、4つ目は3倍です。それ以外の解析では、前回の解析で求めた前景層の方向から計算を始めます。このとき、2つ目以降の各前景層を、それより前の前景層と比べます。どれかとほぼ同じ方向なら、最初の解析のときと同じように回した方向へ置き直してから計算を始めます。

### 4. スケールの決め方

変位のうち前景層の方向に沿った長さを、射影した長さと呼びます。変位と前景層の方向のなす角が90度を超えるときは、射影した長さは負になります。前景層からアルファを求めるときは、射影した長さをスケールで割った値を使います。この値は1で打ち切り、1なら不透明です。スケールが小さいほど、この値は大きくなります。スケールの決め方は「スケール決定」で選びます。

- 物理境界: 背景色から前景層の方向へ進み、sRGBで表せる色の範囲の端に達するまでの距離をスケールにします。距離は二分探索で求め、2を上限にします。背景色からその方向へほとんど進めないときは、スケールはごく小さな値になります。
- 不透明基準: 前景層に割り当てた各画素の変位を、その前景層の方向へ射影します。射影した長さを短いほうから数え、「不透明基準値」の割合に達した長さをスケールにします。集計は0から1までを256等分した区間ごとに行い、割合に達した区間の中央の値を使います。0以下の長さは数えず、1以上の長さは最後の区間に数えます。射影した長さが正になる画素が1つも無い前景層は、物理境界と同じ決め方にします。
- 前景色指定: Oklabで「前景色」から背景色を引いた差を、背景色から白へ向かう方向へ射影し、その長さをすべての前景層のスケールにします。この長さが0以下になる「前景色」では、スケールはごく小さな値になります。背景色が白のときは、どの「前景色」でもこの長さは0以下になります。スケールは背景色から白へ向かう方向で測った長さです。前景層からアルファを求める画素では、アルファを前景層の方向へ射影した長さから求めるため、「前景色」と同じ色の画素が不透明になるとは限りません。

スケールがごく小さな値の前景層からアルファを求める画素は、射影した長さが正なら、その長さがごく短い場合を除いて不透明になります。

スケールは、前景層からアルファを求める画素にだけ効きます。推定した前景の色からアルファを求める画素では、「スケール決定」「不透明基準値」「前景色」を変えてもアルファは変わりません。前景層から求める画素でも、背景色が色みを持つときは、射影した長さをスケールで割った値が、画素に残る背景色の色みから求めた値を超えない範囲では、スケールが変わってもアルファは変わりません。

「前景色」は「スケール決定」が前景色指定のときだけ、「不透明基準値」は不透明基準のときだけ、設定欄に表示されます。「不透明基準値」を下げるほどスケールは小さくなり、不透明になる画素が増えます。

素材の画素だけが変わって解析し直すときは、スケールを前回の値から新しい値へ一度に移さず、差の4分の1だけ近づけます。素材の範囲か、「背景色」「前景色」「スケール決定」「前景層数」「ノイズ閾値」「色シグマ」「不透明基準値」のどれかが変わったときは、新しい値をそのまま使います。解析し直さないフレームでは、スケールは直前の解析で決めた値のまま変わりません。

### 5. 前景の色とアルファ

前景の色が確かな画素を種と呼びます。前景の色は、種の色から始めて周りの画素へ伝えて推定します。

種は、次のように見分けます。Oklabで、黒と背景色を通る直線から画素の色までの距離を測ります。この直線のうち、黒から背景色の方へ延びる側には、線形RGBでR、G、Bの比が背景色と同じで、明るさだけが違う色が並びます。直線からの距離が、直線から白までの距離以上ある画素を種にします。背景色のR、G、Bの値がすべて等しく、黒や白や灰色のように色みを持たない場合は、どの画素も種にしません。

伝える処理では、種も含めた各画素で、その画素を中心とする9×9画素の範囲にある前景の色を候補にします。ただし、候補にするのは、中心の画素の色が、線形RGBで背景色とその前景の色を通る直線の近くにある場合だけです。近いとみなす距離は、前景の色と背景色の差の0.35倍までです。候補のうち、線形RGBで黒と背景色を通る直線から最も離れた前景の色を選びます。この処理を16回繰り返すため、前景の色は種から縦横に最大64画素まで伝わります。種の前景の色も、近くの前景の色に置き換わることがあります。最後の回で候補が1つも無い画素では、前景の色を推定できません。

前景の色を推定できた画素では、画素の色を背景色と前景の色が混ざった色とみなします。線形RGBで、背景色と前景の色を結ぶ線分のどの位置に画素の色があるかで、アルファを求めます。背景色の端が0、前景の色の端が1です。ただし、画素の色から線分までの距離が、前景の色と背景色の差の0.25倍を超えるときは、この求め方を使わず、前景層からアルファを求めます。前景の色からアルファを求めた画素では、推定した前景の色を、出力する前景の色にします。

前景の色を推定できなかった画素も、前景層からアルファを求めます。前景層からアルファを求めるときは、変位を各前景層の方向へ射影し、射影した長さが最も長い前景層を選びます。分割で割り当てた前景層は、ここでは使いません。射影した長さがどの前景層でも0以下の画素は、透明にします。

射影した長さが正の画素では、次の2つの値のうち、大きいほうをアルファにします。1つ目は、射影した長さをスケールで割った値です。2つ目は、画素の色に背景色の色みがどれだけ残っているかをもとに求める値です。線形RGBで、画素の色と背景色から、それぞれと同じ輝度の灰色を引いて色みを取り出します。画素の色みに背景色の色みが何倍含まれるかを求め、その倍率を1から引きます。どちらの値も0から1の範囲に収めます。背景色が色みを持たないときは、1つ目の値だけを使います。前景層からアルファを求めた画素では、線形RGBで画素の色から背景色の混ざった分を除き、アルファで割った色を、出力する前景の色にします。

アルファの求め方によらず、出力する前景の色には「スピル除去と前景出力」に書いた処理をかけます。

「エッジ柔らかさ」は、アルファの低い側を切り捨てる割合です。アルファからこの割合を引き、1からこの割合を引いた幅で割って0から1へ広げ直します。たとえば50%では、0.5以下のアルファは0になり、0.75は0.5になります。アルファが上がる画素は無く、100%未満では不透明の画素は不透明のままです。上げても縁はぼけず、求めたアルファの半透明の部分が削れて境目がはっきりします。縁に限らず、求めたアルファが0と1の間にあるすべての画素に効きます。削るのは求めたアルファだけで、素材のアルファは削りません。100%ではすべての画素が透明になります。

出力のアルファは、「エッジ柔らかさ」をかけたあとのアルファに、素材のアルファを掛けた値です。

### 6. スピル除去と前景出力

スピルは、背景の色が前景に映り込んだ色かぶりです。Oklabのaとbの平面では、色みの無い灰色が原点に来ます。原点から背景色への向きを、背景色の色みの向きと呼びます。背景が緑なら、背景色の色みの向きは緑みの向きです。スピル除去では、前景の色が持つこの向きの成分から「スピル許容」を引きます。残りに「スピル除去」の割合を掛け、その分を前景の色から取り除きます。変えるのはaとbだけで、明るさのLは変えません。背景色からは色みの向きだけを使い、背景色の色みの強さは取り除く量に影響しません。

スピル除去は縁に限らず、出力するすべての画素の前景の色に効きます。映り込みかどうかは区別しません。前景そのものの色みでも、背景色の色みの向きとのなす角が90度未満なら、取り除く対象になります。緑の背景なら、緑の服だけでなく、黄色や水色の前景も緑みが減ります。背景色が色みを持たないときは、スピル除去を行いません。

「スピル除去」は、色かぶりを取り除く割合です。上げると強く取り除き、0%では前景の色を変えません。

「スピル許容」は、前景の色が持つ、背景色の色みの向きの成分のうち、スピル除去で取り除かずに残す量です。上げると取り除く量が減ります。前景の色が持つこの向きの成分が「スピル許容」以下なら、その前景の色は変わりません。

「前景出力」をオフにすると、前景として残す部分を白で出力し、背景として取り除く部分は透明のままにします。半透明の部分は、アルファに応じた半透明の白になります。スピル除去はかかりません。アルファだけを確かめるときに使います。

| スピル許容 | 数値 | 0 | 0〜0.5 | 対応 | 前景の色が持つ、背景色の色みの向きの成分のうち、スピル除去で取り除かずに残す量です。上げると取り除く量が減ります。直接入力では1まで指定できます。 |

## 制限事項

- AviUtl向けのEXO出力には対応していません。
- YMM4が使うGPUでDirect3D 12デバイスを取得できない場合や、YMM4が使うDirect3D 11デバイスとの共有テクスチャや共有フェンスを作成できない場合は、画素をCPU経由で受け渡します。前者では、GPUを性能の高い順に探し、最初にDirect3D 12デバイスを作れたGPUで解析します。どのGPUでも作れないときは、CPUでDirect3D 12を動かすWARPで解析します。後者では、YMM4が使うGPUのまま解析します。画素をCPU経由で受け渡すときは、素材の画素を毎フレームCPUへ読み戻し、前回読み戻した画素と比べます。解析するフレームでは、読み戻した画素を解析に使い、推定した前景の色もCPUへ読み戻してからDirect2Dへ渡します。
- 解析に使うDirect3D 12デバイスを用意できない場合や、Direct2Dのカスタムエフェクトを作成できない場合は、エフェクトを適用せず入力映像を表示します。
- 解析には、現在のフレームの色とアルファに加えて、前回の解析の結果を使用します。外部画像と学習済みモデルは使用しません。
- 計算領域は、エフェクトへ入力された素材の範囲と同じ大きさです。
- 背景色のR、G、Bの値がすべて等しい場合だけ、黒や白や灰色のように色みを持たない背景色として扱います。値が1つでも違えば、灰色に近い背景色でも、そのわずかな色みをもとに種を見分け、アルファを求め、スピル除去で取り除く向きを決めます。色みを持たない背景色では種を見分けないので、どの画素でも前景の色を推定できません。アルファは前景層の方向とスケールだけから求め、スピル除去は行いません。
- 処理量とGPUメモリ使用量は、素材の画素数に応じて増えます。

## 注意事項

- 前景層: 近くにあって色も近い画素どうしで変位の方向を平滑化したあと、方向の似た画素をまとめたものです。前景層の数は、前景層数の設定で1つから4つまでの範囲で決めます。出力を分けるものではなく、アルファを求めるのに使う方向とスケールを決めるためのものです。
- 処理負荷: 素材の画素が変わったフレームでは解析し直します。変わった画素が一部だけなら、変位の方向の平滑化はその周りだけでやり直し、処理を抑えます。ただし、背景色、ノイズ閾値、色シグマのどれかが変わったときは、平滑化を全体でやり直します。変わった画素が全体の25%を超えたときも同じです。前景層への分割と前景の色の推定は、変わった画素が一部だけでも、素材全体でやり直します。
- キャッシュ: 素材の範囲と画素、背景色、前景色、スケール決定、前景層数、ノイズ閾値、色シグマ、不透明基準値が変わらないフレームでは、前回の解析の結果をそのまま使います。素材の画素は、1つでも変われば解析し直します。エッジ柔らかさ、スピル除去、スピル許容、前景出力だけを変えたフレームでは、解析し直しません。動画のように素材の画素が変わるフレームと、ノイズ閾値、色シグマ、不透明基準値をアニメーションで変えたフレームでは、毎回解析し直すため、処理が重くなります。不透明基準値は、スケール決定が不透明基準のときだけ設定欄に表示されます。ほかの決め方にしても、不透明基準値へ付けたアニメーションは残り、値が変わるフレームでは解析し直します。前景層数をアニメーションで変えたフレームでは、丸めた整数が変わるときだけ解析し直します。
- 前回の解析の引き継ぎ: 同じフレームの同じ素材でも、シークして表示したときと、前のフレームから続けて再生したときで、結果が違うことがあります。直前に処理したフレームの解析の結果を引き継ぐためです。前景層の方向は、最初の解析のときと、前景層数が変わったときを除き、前回の解析で求めた方向から計算を始めます。そのため、解析し直すパラメータを変えて元に戻したときも、前と同じ結果になるとは限りません。スケールは、素材の画素だけが変わって解析し直すフレームで、前回の値から新しい値へ、差の4分の1だけ近づけます。動画で絵柄が大きく変わった直後は、スケールが数フレームかけて新しい値へ近づきます。素材とパラメータが変わらないフレームでは解析し直さないので、そのあいだスケールは途中の値のまま変わりません。引き継ぎ方は「前景層への分割」と「スケールの決め方」に書いています。
- エッジ柔らかさ: 上げても縁はぼけず、求めたアルファの半透明の部分が削れて境目がはっきりします。縁に限らず、求めたアルファが0と1の間にあるすべての画素に効きます。削るのは求めたアルファだけで、素材のアルファは削りません。100%ではすべての画素が透明になります。
- スピル除去: 縁に限らず、出力するすべての画素の前景の色に効きます。映り込みかどうかは区別しません。前景そのものの色みでも、背景色の色みの向きとのなす角が90度未満で、その向きの成分がスピル許容を超えれば、取り除く対象になります。前景出力をオフにしたときは、スピル除去はかかりません。
- 透明部分: 出力範囲は素材と同じです。変位の長さがノイズ閾値の半分に満たない画素と、素材でアルファが0の画素は、必ず透明になります。ほかの画素も、エッジ柔らかさをかけたあとのアルファが0なら透明になります。
- 更新通知: エフェクトを最初に生成したときに、YMM4の実行中に一度だけ新しい正式版を確認します。更新情報を取得できない場合は通知せず、そのまま動作します。プレリリースは通知の対象に含めません。
- 不具合の自動送信: 想定していない例外が起きたときは、その内容を開発者へ自動で送信します。内容は「不具合の報告」に書いています。
- 本プラグインを使用する前に、YMM4のプロジェクトファイルのバックアップを作成することを推奨します。

## 不具合の報告

本プラグインは、想定していない例外が起きたときに、その内容を開発者へ自動で送信します。同意は求めず、常に送信します。

送信する情報は次のとおりです。

| 種類 | 内容 |
|---|---|
| 例外 | 型の完全名、メッセージ、スタックトレース |
| 発生位置 | モジュール名、関数名、ファイル名、行番号 |
| プラグイン | アセンブリ名、バージョン |
| 実行環境 | OSの名前とバージョン、.NETのバージョン、CPUのアーキテクチャ、論理プロセッサ数 |
| 識別子 | YMM4の起動ごとに決まるセッション識別子、報告ごとの識別子 |

メッセージとファイル名は、送信の前に置き換えを通します。置き換えるのは、Windowsのユーザー名、ユーザーフォルダー、AppDataのパス、マシン名、ドメイン名、メールアドレス、IPv4アドレスです。送信元のIPアドレスは受信側へ渡す手前で取り除いています。

映像の中身とプロジェクトの内容は送信しません。継続して個人を追跡する識別子も持ちません。セッション識別子はYMM4を起動し直すと別の値になります。

送信するのは想定していない例外だけです。YMM4が本プラグインのエフェクトを作るとき、フレームごとに更新するとき、入力をつなぎ直すとき、破棄するときと、Direct2Dがシェーダーの定数を書き込むときに起きた例外を報告し、その後はYMM4へそのまま渡します。更新の確認で起きた例外は、更新情報の取得の失敗を除いて報告し、YMM4へは渡しません。画面の操作やバックグラウンドの処理で未処理になった例外も報告しますが、本プラグインのコードが関わる例外に限ります。本プラグインの外で起きた例外は送信しません。

次の失敗は送信しません。

| 種類 | 例 |
|---|---|
| 効果をかけないだけで済ませるもの | 解析に使うDirect3D 12デバイスを用意できない、Direct2Dのカスタムエフェクトを作成できないときに、エフェクトを適用せず入力映像を表示したとき |
| CPU経由の処理で済ませるもの | YMM4が使うGPUでDirect3D 12デバイスを取得できない、YMM4のDirect3D 11デバイスとの共有テクスチャや共有フェンスを作成できないときに、画素をCPU経由で受け渡したとき |
| 更新の確認の通信の失敗 | manjubox.netとGitHubのどちらからも更新情報を取得できない |

送信できなかった報告はYMM4のユーザーフォルダーへ退避します。次にYMM4を起動したあと、本プラグインのエフェクトを生成するか、同じくYMM4-Telemetryで報告する別のプラグインが動き始めると、退避した報告を1回の起動で10件まで送り直します。送信も再送も非同期に行うため、通信を待って起動と描画が遅くなることはありません。

実装は [YMM4-Telemetry](https://github.com/routersys/YMM4-Telemetry) をサブモジュールとして取り込んでいます。
